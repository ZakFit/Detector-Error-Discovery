# Модуль person для команды

Готовый CPU-пайплайн: **DEIMv2-M + RTMPose-m Halpe26 + логистическая регрессия**. Рассчитаны оценки для всех **153 person-детекций test**. Итоговый файл — `outputs/person_scores.csv`, колонки `id,score`. Чем выше score, тем подозрительнее исходный бокс. Числа используются для ранжирования; точная вероятностная калибровка не заявляется.

## Как добавить людей в сабмит команды

Распаковать архив так, чтобы папки `person_pipeline` и `data` лежали рядом. В `data` должны быть исходные `csv/test.csv` и остальные файлы хакатона. Команды выполнять из их общей родительской папки, Python 3.12.

```powershell
python -m pip install -r person_pipeline/requirements.txt
python person_pipeline/pipeline.py merge --base team_submission.csv --destination submission_with_people.csv
```

`team_submission.csv` заменить на путь к основному сабмиту команды. Файл с готовыми person-score модуль найдёт сам. В текущем рабочем проекте уже создано окружение: вместо `python` можно использовать `.\.venv-person\Scripts\python.exe`.

**По умолчанию используется режим `rank`.** Модуль сортирует людей по новым оценкам и перераспределяет между ними существующие person-score из основного сабмита. Так сохраняется масштаб оценок команды относительно других классов. Остальные 209 строк сохраняют свои score. Сопоставление выполняется по `id`, порядок строк не важен. Скрипт проверяет полный набор 362 тестовых id, отсутствие повторов и диапазон score.

Прямая подстановка новых значений доступна через `--mode direct`, но в нашей проверке она ухудшила общую AP из-за смены масштаба. Для первого командного эксперимента использовать стандартный `rank`. Если у исходного сабмита все person-score одинаковые, этот режим не сможет изменить ранжирование: нужно отдельно согласовать масштаб новых оценок.

`person_scores.csv` содержит только людей. В Kaggle нужно отправлять **полный файл**, созданный командой `merge`.

## Что делает модель

1. DEIMv2-M анализирует полный кадр и выдаёт независимые боксы людей.
2. Для каждого исходного person-бокса выбирается наиболее пересекающийся внешний бокс. Формируется окно с контекстом вокруг исходной и найденной областей.
3. RTMPose-m определяет 26 точек тела. Учитываются уверенность точек, положение за границами исходного бокса и отсутствие уверенных стоп.
4. Десять признаков, включая исходный confidence и расхождения геометрии, поступают в логистическую регрессию с L2 и `C=0.1`.

Нейросети предобучены и заморожены. Обучается только небольшой оценщик. Итоговая версия обучена на всех 84 train-детекциях person. Тестовые изображения использованы для инференса; ручных тестовых меток и ручных подстановок ответов нет. Временной контекст и машинный пул в этой версии не используются.

## Проверка качества

Каждый UTC-день проверялся моделью, обученной на другом дне. Стандартизация признаков также обучалась только на обучающем дне. Проверены четыре заранее заданных варианта: confidence, IoU с детектором, детектор + LR, детектор + поза + LR. Последний улучшил person AP на обоих днях и выбран по лучшему результату на худшем дне.

| Отложенный день | Person AP: 1-confidence | Person AP: наш оценщик | Общая AP: исходная | Общая AP: после rank-объединения |
|---|---:|---:|---:|---:|
| 25 октября | 0,8021 | 0,9187 | 0,8607 | 0,8723 |
| 26 октября | 0,5959 | 0,7270 | 0,7648 | 0,8048 |

Общая AP рассчитана без table, с `1-confidence` у остальных классов. Это сравнение с базовым решением организаторов. Реальные score командного `reannotate_mean` не были предоставлены, поэтому улучшение именно его не измерено. Выбор модели сделан на этих же двух небольших отложенных днях; независимой оценки выбранной версии и Public-результата пока нет.

Числа в столбце «Person AP: наш оценщик» относятся к исходным непрерывным score. После переноса на значения базового сабмита появляются его совпадающие значения: person AP составляет 0,9147 и 0,7152. Общая AP в таблице уже учитывает этот эффект.

Подробности: `outputs/validation.json` и `outputs/validation_oof.csv`.

## Воспроизведение

В полном архиве есть обе готовые ONNX-модели и обученный оценщик `outputs/scorer.json`. GPU и PyTorch для обычного запуска не нужны.

```powershell
# Получить признаки из всех train/test изображений.
python person_pipeline/pipeline.py extract --threads 4

# Повторить проверку по дням и обучение финального оценщика.
python person_pipeline/pipeline.py evaluate

# Либо применить уже сохранённый оценщик без повторного обучения.
python person_pipeline/pipeline.py predict

# Проверить геометрию и объединение по id.
python person_pipeline/test_pipeline.py
```

Для нового test с тем же форматом сначала выполнить `extract --split test`, затем `predict`. Кэш предсказаний находится в `outputs/cache`; он проверяет хеш изображения, модели и окно позы. При изменении входных таблиц необходимо повторить извлечение признаков. Метаданные и хеши моделей хранятся рядом с признаками.

На Core i5-13420H, 4 потока, batch=1, FP32 после прогрева: медиана детектора **0,494 с/кадр**, позы **0,016 с/человек**. Измерены 12 train-кадров и 32 окна; пик памяти процесса — около **539 МиБ**. Измерение включает подготовку входа и обработку выхода модели, исключает чтение файлов и загрузку весов. Полный набор содержит 117 кадров и 237 окон. Подробности — `outputs/benchmark.json`.

Опциональные скрипты `benchmark.py` и `review_train.py` требуют соответственно `psutil` и `matplotlib`. Они не нужны для получения person-score и объединения сабмита.

## Источники весов и экспорт

- [DEIMv2-M](https://github.com/Intellindust-AI-Lab/DEIMv2), [публичные веса](https://huggingface.co/Intellindust/DEIMv2_DINOv3_M_COCO). Код зафиксирован на `f005f50ce565e63f6c298feccb51901a98c3d035`, веса — на `c5db2fc6f4d9e59635cfc2effaf097bc9a293beb`.
- [RTMPose-m Halpe26, 256×192](https://github.com/open-mmlab/mmpose/tree/main/projects/rtmpose#26-keypoints), [официальный ONNX-архив](https://download.openmmlab.com/mmpose/v1/projects/rtmposev1/onnx_sdk/rtmpose-m_simcc-body7_pt-body7-halpe26_700e-256x192-4d3e73dd_20230605.zip).

URL и SHA-256 исходных файлов записаны в `assets/sources.json`, хеши готовых моделей — в `assets/model_manifest.json`. Лицензии приложены в `assets`: DEIMv2 License (Non-Commercial) и Apache-2.0 для RTMPose. Наше изменение DEIMv2 — экспорт весов в ONNX с batch=1; веса нейросети не дообучались. Если готовых ONNX-файлов нет, восстановить их можно так:

```powershell
python -m pip install -r person_pipeline/requirements-export.txt
python person_pipeline/setup_assets.py
python person_pipeline/export_detector.py
```

DEIMv2 экспортирован на CPU с batch=1. Проверка против PyTorch: среди первых 50 выходов классы совпали, максимальное расхождение координат — 0,000245 пикселя, score — 0,0000041. Проверка сохранена в `assets/export_check.json`. При загрузке safetensors восстановлены только два имени общих тензоров `up` и `reg_scale`; все веса загружены со строгой проверкой.
