# Detector-Error-Discovery

Решение кейса RASCAR «Аудит детектора объектов» (Kaggle `rascar-hack-case-1`, данные — КИРА).
Камера в обеденном зале кафе каждые 30 секунд отправляет кадр, детектор ставит боксы: люди, руки, чашки, подносы.
Нужно ранжировать детекции так, чтобы ошибочные оказались в начале очереди проверки. Метрика — Average Precision.

**Лучший Public: 0.842** — `python final_ft.py ft_all.csv` → `submissions/sub_ft_all.csv`.

## Главная идея: переразметить кадр заново и сравнить

Детекция считается верной, если её можно сопоставить с ручным боксом того же класса при IoU ≥ 0.6.
Значит, лучший признак ошибки — не уверенность детектора, а то, **насколько бокс совпадает с тем, как разметил бы
человек**. Мы «переразмечаем» каждый кадр независимыми моделями и оцениваем детекцию по IoU с их боксами:

```
кадр ──► дообученный YOLO11n (учится на ручной разметке train) ─────────────► IoU ─┐
     └─► открытые модели без обучения:                                              ├─► score = среднее
           руки, чашки, подносы — OWLv2 на увеличенном окне вокруг детекции ─► IoU ─┤      (1 − согласие)
           люди — OWLv2 + YOLOv8-seg + YOLO11-pose, «полный» бокс тела       ─► IoU ─┘
                  по ключевым точкам (ноги под столом), уверенность детектора
```

Обучаемая часть одна — дообучение YOLO11n на 84 размеченных кадрах train (~10 мин на CPU);
всё остальное — детерминированные правила поверх готовых моделей, весов в смеси не подбирали.

|---|---|---|

## Запуск

```bash
python3 -m venv .venv
.venv/bin/pip install pandas numpy scipy scikit-learn pillow lightgbm torch torchvision ultralytics transformers kagglehub
# данные (нужен Kaggle-токен и принятые правила соревнования)
KAGGLEHUB_CACHE=$PWD/data/.kagglehub .venv/bin/python -c "import kagglehub; kagglehub.competition_download('rascar-hack-case-1')"
ln -sfn .kagglehub/competitions/rascar-hack-case-1 data/raw

.venv/bin/python final_ft.py ft_all.csv      # лучший сабмит из уже посчитанных ответов моделей (data/*.csv)
```

Ответы моделей лежат в `data/*.csv` (в git), поэтому сабмит собирается за пару минут.
Пересчёт с нуля на CPU (~1.5 ч):

```bash
.venv/bin/python second_opinion.py <yolov8s-seg.pt> <yolo11m-pose.pt>   # COCO-модели: люди, позы
.venv/bin/python owl_opinion.py                                         # OWLv2 на полном кадре
.venv/bin/python owl_zoom.py                                            # OWLv2 на увеличенных окнах
.venv/bin/python finetune_yolo.py                                       # дообучение YOLO11n (d25, d26, all)
.venv/bin/python final_ft.py ft_all.csv
```

## Структура

| файл | роль |
|---|---|
| `final_ft.py` | **итоговый сабмит**: переразметка + дообученный YOLO |
| `finetune_yolo.py` | дообучение YOLO на ручной разметке; прогоны по дням для честной проверки |
| `eval_finetune.py` | проверка дообученной модели на отложенном дне |
| `reannotate.py` | переразметка открытыми моделями (0.712 сама по себе) |
| `second_opinion.py`, `owl_opinion.py`, `owl_zoom.py` | прогон независимых моделей → `data/*.csv` |
| `features.py` | загрузка данных, IoU, базовые признаки |
| `opinion_features.py`, `final.py` | вспомогательные признаки и решение 0.684 (используются переразметкой) |
| `experiments/` | ранние эксперименты: табличные модели, правила, фон зала, предсказатель IoU на эмбеддингах resnet/dinov2/sam |
| `submissions/` | все сабмиты |

Скрипты из `experiments/` запускаются из корня: `python -m experiments.solve`.

## Валидация

Train — два дня (25.10 и 26.10). Обучаемся на одном дне, проверяем на другом, класс `table` исключаем, как в test.
Улучшение засчитываем, только если оно есть на обоих днях: признаки, отобранные перебором на 198 строках,
на Public проваливались. Разрыв train → Public систематический (~0.15–0.2), поэтому ориентир — направление, а не уровень.

## Модели и веса

| модель | для чего | источник |
|---|---|---|
| YOLO11n (дообучение) | переразметка в стиле разметчика | https://github.com/ultralytics/assets/releases |
| YOLOv8s-seg, YOLO11m-pose | люди, ключевые точки тела | https://github.com/ultralytics/assets/releases |
| OWLv2 base | поиск рук, чашек, подносов, людей по тексту | https://huggingface.co/google/owlv2-base-patch16-ensemble |

Ручная разметка test не используется: по правилам она запрещена. Все правила применяются кодом одинаково ко всем строкам.
